# STEP-2：核心底座、开票、催收、权限与日志

GitHub：[#18](https://github.com/jake2ace/SDC-Tracker/issues/18)

**状态：TODO · 职责：后端开发 · 依赖：STEP-1 ([#17](https://github.com/jake2ace/SDC-Tracker/issues/17))**

## 目标

建立能启动、持久保存、执行权限检查的后端新基线，支持发票草稿和人工确认的演示催收。

## 范围与允许目录

`src/`、`data/seed/`、`tests/`、`scripts/`、`docs/` 及服务端工程配置；接口变更同步 `contracts/`。涉及 `web/` 页面的改动交给前端任务负责人。

## 完成标准

- [ ] 可初始化/重置合成数据；客户、发票及日志刷新和重启后保留；不同演示企业的数据隔离。
- [ ] 发票金额、到期日及余额由后端计算/验证；生成草稿、批准与模拟开票有明确状态；重复操作不产生副本。
- [ ] 仅未结清且符合规则的发票进入催收；消息可人工检查、修改、确认后模拟发送，保存来源及发送状态。
- [ ] 权限校验在后端执行；未批准、被驳回、越权或接口失败均不推进业务状态，并保留审计记录。
- [ ] 提供可运行启动命令、环境变量示例与健康检查；交给 STEP-8 ([#24](https://github.com/jake2ace/SDC-Tracker/issues/24)) 先验证部署骨架。

## 证据

启动/重启记录、关键规则测试、审批和失败日志样例；重建版重新验证，不引用旧版测试数量作为完成证明。
