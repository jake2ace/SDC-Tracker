# SDC Tracker

SDC Hackathon 2026 · Domain 2 · 队伍 Lets go

**项目交付 → 自动开票 → AI 催收 → 30 天现金流预测。**

## 初赛最终目标

| 功能 | 必须实现的效果 |
|---|---|
| 自动开票 | 项目阶段完成后，根据付款约定生成正确草稿；人工批准后模拟开票并记录结果。 |
| AI 催收 | 识别未付的逾期发票，根据金额、逾期天数和历史生成可修改的提醒；人工确认后模拟发送，付款后停止催收。 |
| 现金流预测 | 展示未来 30 天预计余额，对比按时与延迟到账，标出低于安全线的日期和金额。 |

三项全部属于初赛范围，必须共享数据并串成完整流程。业务逻辑真实运行；公司、合同等使用团队自建合成数据，外部会计和消息接口由我们模拟。

## 完成标准

- [ ] 三个功能使用同一组数据，能够完整演示。
- [ ] 开票金额、付款节点和账期正确；重复操作不重复开票。
- [ ] 未批准、被驳回或无权限时不能执行；接口失败不显示成功。
- [ ] AI 提醒准确引用欠款，文案可修改，人工批准后才模拟发送。
- [ ] 付款后停止催收，同一次提醒不重复发送。
- [ ] 30 天现金预测可以比较按时与延迟到账，结果能用收支明细核对。
- [ ] 收款日期或状态变化后更新预测，实际与预计收款不重复计算。
- [ ] 状态与日志持久保存，换一家公司的合成数据仍能运行。
- [ ] 部署链接可访问，按 README 可在干净环境复现。

### 本地启动

需要 **Node.js 22.13 或更新版本**。使用 Node 内置 HTTP、SQLite 和测试工具，没有第三方运行依赖，无需先执行 `npm install`。

```sh
git clone https://github.com/jake2ace/SDC-Tracker.git
cd SDC-Tracker
# 若基础工程仍在 PR 中，先切换到该 PR 分支：
git switch codex/issue-2-app-foundation
npm start
```

打开 <http://127.0.0.1:3000>。开发时可用 `npm run dev`，运行自动验收用 `npm test`。

首次启动会创建 `data/sdc-tracker.sqlite` 及两组明确标注的合成工作区／演示身份；数据库文件不会提交到 Git。刷新页面或重启同一个数据库文件，操作和日志都会保留。

### 基础流程演示

1. 选择 Studio A 的 **Operator**，创建草稿并提交审批。
2. 切换同工作区的 **Reviewer**，批准或驳回草稿；只有批准后才能执行。
3. 可以先模拟一次接口失败，查看失败日志，再重试成功；成功后不能重复执行。
4. 切换 **Viewer** 验证只读；切换 Studio B 验证工作区隔离。

身份选择器是比赛允许的模拟身份入口，任何访问该演示的人都能选择演示角色；它不是真实注册／登录系统。后端使用服务端会话、角色检查与 CSRF 校验，不信任浏览器传入的角色或工作区。

配置项见 [.env.example](.env.example)。本地默认读取进程环境；如果创建了 `.env`，使用 `node --env-file=.env src/server.js` 加载。Replit 的 Run 配置已提供，但本仓库不会自动创建账号、部署或产生赞助工具使用证明。SQLite 适合本地单实例原型；发布前须确认托管环境的磁盘持久性或接入持久数据库。
